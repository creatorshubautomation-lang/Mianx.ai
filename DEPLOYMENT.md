# Mianx.ai — Vercel Deployment Guide

This guide covers deploying Mianx.ai to Vercel.

## ⚠️ Important: Database Requirement

**SQLite (default) does NOT work on Vercel** because Vercel's serverless functions have a read-only filesystem. You MUST use an external database.

### Recommended: Vercel Postgres (free tier)

1. Go to your Vercel project → Storage → Create Database → Postgres
2. Get the connection string (looks like `postgres://...`)
3. Set `DATABASE_URL` env var in Vercel

### Alternative options:
- **Neon** (serverless Postgres, free tier) — https://neon.tech
- **Supabase** (Postgres + auth + storage) — https://supabase.com
- **Turso** (SQLite-compatible, edge-friendly) — https://turso.tech
- **PlanetScale** (MySQL serverless) — https://planetscale.com

## Deployment Steps

### 1. Push to GitHub (already done)
Repository: https://github.com/creatorshubautomation-lang/Mianx.ai

### 2. Import to Vercel
1. Go to https://vercel.com/new
2. Import the `creatorshubautomation-lang/Mianx.ai` repo
3. Vercel will auto-detect Next.js settings

### 3. Set Environment Variables
In Vercel project settings → Environment Variables, add:

| Variable | Value | Notes |
|----------|-------|-------|
| `DATABASE_URL` | `postgres://...` | From your Vercel Postgres / Neon / Supabase |
| `NEXTAUTH_SECRET` | (random 32+ char string) | Generate with `openssl rand -base64 32` |
| `NEXTAUTH_URL` | `https://your-app.vercel.app` | Your final Vercel URL (add after first deploy) |

### 4. Switch Prisma to Postgres

The default `schema.prisma` uses SQLite. For Vercel Postgres, change the datasource:

```prisma
datasource db {
  provider = "postgresql"  // ← change from "sqlite"
  url      = env("DATABASE_URL")
}
```

Also, in `schema.prisma`, replace `String` arrays (not supported in Postgres) — they already use JSON strings in our schema, so you're good.

### 5. Build Command
Vercel auto-detects `next build`. The Prisma client is generated by the `postinstall` script automatically (see `package.json`).

If needed, override Build Command to:
```
prisma generate && next build
```

### 6. Push Schema to Database
After first deploy, run migrations against your production DB:

```bash
# Set DATABASE_URL to your production Postgres
export DATABASE_URL="postgres://your-prod-db-url"

# Push schema
bun run db:push
```

Or use Prisma Studio to inspect:
```bash
bunx prisma studio
```

## Common Issues

### "TypeError: Invalid URL"
- **Cause**: Build-time code trying to parse empty URL
- **Fix**: Already addressed in latest commit. Make sure `NEXTAUTH_URL` or `VERCEL_URL` is set.

### "Database connection failed" at runtime
- **Cause**: `DATABASE_URL` not set, or DB not provisioned
- **Fix**: Add a Postgres database in Vercel Storage tab

### "PrismaClient initialization failed"
- **Cause**: Prisma client not generated during build
- **Fix**: Add `prisma generate` to Build Command

## Local Development (SQLite)

For local dev, SQLite works fine. Just:
```bash
cp .env.example .env
bun install
bun run db:push
bun run dev
```

## Tech Stack Notes

- **Framework**: Next.js 16 (App Router)
- **Auth**: NextAuth.js v4 (JWT strategy, no DB sessions — works on serverless)
- **ORM**: Prisma 6
- **AI**: z-ai-web-dev-sdk (works on serverless, no state needed)
- **State**: Zustand (client-side only, no server impact)

The app is designed to be serverless-friendly: no WebSockets, no long-running processes, no file uploads to local disk.
